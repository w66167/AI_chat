# 校园知答：微信小程序

基于《杭州电子科技大学学生手册》（学生处、教务处编，2017 年 9 月版）的问答小程序。
学生用平常的话提问，小程序给出依据条文整理的回答，并标明出自哪份文件、哪一条、第几页；
每条出处都能点开核对原文，也可以直接按目录翻手册、搜条文。

**小程序本身不带任何知识内容。** 问答、手册目录、条文原文、身份与提问记录全部来自后端（`../backend`），
所以必须先启动后端才能使用。

## 能做什么

| 页面 | 内容 |
| --- | --- |
| 首页 | 提问入口、同学们常问的问题、按事项进入手册 |
| 问答 | 提问 → 回答 + 出处（可点开原文）+ 接下来可能想问的问题；有帮助 / 没解决反馈 |
| 手册 | 28 份文件按 7 类事项分组；条文关键词搜索 |
| 文件 | 一份文件的全部条文，按章分组 |
| 条文原文 | 单条全文、所在页码、上一条 / 下一条、复制、就这一条提问 |
| 提问记录 | 保存在服务端的历史提问，换手机也能看（需绑定在校身份） |
| 我的 | 当前身份、绑定 / 更换身份、能查哪些内容、退出登录 |

不做的事：不查个人成绩、课表等个人业务数据，不代办、不派单、不受理投诉（后端的答复边界，见 `../backend/README.md`）。

## 运行

1. **启动后端**（详见 `../backend/README.md`）：

   ```powershell
   cd ..\backend
   python run.py --port 8000
   ```

   启动时会打印当前状态：生成模型是否启用、登录方式、检索走哪条路径。
2. **微信开发者工具** → 导入项目 → 目录选本 README 所在的 **campus-assistant 文件夹**（不是里面的 `miniprogram`）→ 编译。
3. 开发者工具「详情 → 本地设置」里勾选「不校验合法域名」（项目配置里已设 `urlCheck: false`）。

后端地址只在一处：`miniprogram/utils/api.js` 的 `BASE_URL`。

> **模拟器可以用 `http://127.0.0.1`，真机不行。** 真机预览、体验版和正式发布需要：
> 一个正式的小程序 AppID、一台能公网访问的服务器、已备案的 HTTPS 域名，并在小程序后台把该域名加入「request 合法域名」。

## 登录与身份

**登录**在启动时静默完成（`utils/api.js` 的 `login()`）：`wx.login` 取得 code，连同设备号一起交给后端
`/v1/auth/login`，换回一个令牌，之后每个请求都带着它。

- 后端配置了小程序的 AppID 和 AppSecret → 真实微信登录，用户按微信 openid 识别。
- 没配置 → **开发模式**：按设备号发一个本地账号。「我的」页会明确标出当前是开发模式。
  现在 `project.config.json` 里是游客 AppID（`touristappid`），无法真实登录，所以默认就是这个模式。

**身份**在「我的」页绑定，决定能查什么：

| 身份 | 可查内容 | 提问记录 |
| --- | --- | --- |
| 游客（未绑定） | 国家教育法规（手册前 3 份文件） | 不保存，对话只在内存里 |
| 学生 | 国家教育法规 + 学生手册 25 份校内规章 | 保存在服务端 |
| 教师、行政人员 | 同学生，另有教职工手册（内容待补） | 保存在服务端 |

身份由**后端按令牌认定**，小程序不上报身份——请求里自称教师没有用。
切换身份会清空当前对话（里面可能有新身份无权查看的条文）；已经打开的条文页回到前台时会重新校验。

目前身份是**自行声明**的：学生直接绑定，教师需要口令（后端配置了 `teacher_code` 时）。
这不是真正的在校身份核验，「我的」页如实标注了「尚未经学校统一身份认证核验」。

「知识维护人员 / 知识审核员」是管理端角色，不在小程序里，职责由 `../knowledge_base/scripts/kb_admin.py` 承担。

## 回答的两种形态

后端返回的 `answer_mode` 决定问答页怎么显示：

| `answer_mode` | 含义 | 页面表现 |
| --- | --- | --- |
| `generated` | 大模型依据检索到的条文整理的回答 | 正常字体；出处标题为「依据以下条文整理」，只列模型实际用到的条文 |
| `excerpt` | 条文原文（后端没配模型密钥，或生成失败降级） | 宋体显示原文，超过 220 字折叠；出处标题为「手册原文出自」 |

后端五档 `behavior` 对应页面三种非作答形态：`clarify` →「需要再具体一点」，`refuse_noanswer` →「手册里没有找到依据」，
`refuse_boundary` →「这件事我办不了」。映射写在 `utils/api.js` 的 `toMessage()`。

## 连不上后端时

没有本地知识可以顶替，所以如实提示：

- 问答：气泡里显示「这次没有问成功」和原因，保留问题，点「重新提问」重发。
- 首页、手册、文件、条文、提问记录：整页提示加「重新加载」。
- 「我的」：显示上次缓存的身份，并提示连不上。
- 令牌失效（后端返回 401）时自动重新登录并重试一次，用户无感。

## 界面约定

颜色和字体只在 `app.wxss` 的 `page` 变量里定义。

- 绿色 `--green` 是操作色：按钮、链接、选中状态。
- 朱红 `--seal` 只用于条号，取自红头文件的颜色；宋体只用于手册原文和文件名。
  也就是说，屏幕上出现「朱红 + 宋体」的地方，就是手册原文或它的出处。
- **条文签**（`.slip`）是全小程序唯一的引用样式：左侧朱红竖线、宋体条号、右侧页码。
  问答的出处、搜索结果、文件目录、提问记录用的是同一个，点了都进条文原文页。
- 一组内容放在一个白色面板里，行与行之间用细线分隔。

## 检查

```powershell
node scripts/check.js             # 结构、语法、联网规则、不带知识与密钥、事件处理函数、本机状态逻辑（不需要后端）
python scripts/check-wxml.py      # WXML 标签闭合
node ..\backend\tests\smoke_miniprogram.js   # 七个页面接真实后端走完整流程（自己起一个后端，跑完即关）
```

第三条在 Node 里模拟微信运行环境，跑的是页面的真实代码和真实后端，覆盖：
静默登录 → 游客的可查范围 → 绑定身份 → 提问并点出处看原文 → 手册目录与搜索 → 提问记录 →
教师口令 → 解除身份 → 断网与恢复 → 令牌失效 → 退出登录。它不渲染界面，
**界面效果仍需在微信开发者工具里看**。

## 还没做

- **真实身份核验**：现在是自行声明。上线需要接学校统一身份认证，由那边确认「这个微信是哪位学生 / 教师」。
- **流式输出**：回答是整段返回的，生成时显示「正在查手册」。
- **教职工手册**：没有语料，注册表里标着「内容待补」。
- **图片提问、语音输入**：没有。
- **手册版本**：只有 2017 年 9 月版。手册前言写明内容与学校文件不符的以学校文件为准，条文页和首页都保留了这句提示。

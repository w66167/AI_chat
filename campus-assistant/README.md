# 校园知答：微信小程序演示框架

这是依据《校园智能客服与知识问答系统需求分析说明书》搭建的原生微信小程序。直接在微信开发者工具中导入即可开始本地演示，不需要 npm 安装、后端、云开发环境或 HTTPS 域名。

## 现在可以演示什么

- 首页：常用服务、常见问题、已发布知识数量。
- 问一问：已发布知识的关键词与相似问法检索、简单追问、分类澄清、无答案提示、来源和版本、有帮助/待改进反馈。
- 办事指南：按分类与关键词查找，查看办理步骤、咨询窗口和资料来源。
- 我的：切换**游客 / 学生 / 教师、行政人员**三种使用者身份，查看本机统计与知识库清单。
- 身份与知识库：每个身份有自己能访问的知识库（游客＝公开指南，学生＝＋学生手册，教师＝＋教职工手册），
  「我的」页列出每个库的版本与建设状态；知识条目按所属知识库的身份范围过滤，回答里标注「知识库 · 文档 · 条号/页码」。
- 演示复位：恢复 22 条初始知识（分属三个知识库），方便下一轮展示。

**用户端小程序只有使用者身份。** 「知识维护人员 / 知识审核员」是对系统负责而不是使用系统的内部角色，
不在小程序里（没有身份切换、没有工作台页面），知识起草与审核发布由管理端工具
`knowledge_base/scripts/kb_admin.py` 完成，详见下文「身份与知识库」。

**当前是本地检索原型，没有接入大模型、RAG、OCR、真实学校登录、真实个人业务查询或报修工单。** 所有样例制度、窗口和时间都明确标注为演示资料。没有配置未经核实的学校电话和外部链接。

## 导入微信开发者工具

1. 打开微信开发者工具，选择“小程序”，然后“导入项目”。
2. 项目目录选本 README 所在的 **campus-assistant 文件夹**，不要选它里面的 miniprogram 文件夹。
3. 项目名可填写“校园知答”。配置里的 `touristappid` 用于游客本地调试。如果工具提示需要 AppID，按界面提供的“测试号”或“不使用 AppID / 游客模式”创建；已有小程序 AppID 也可以使用。
4. 如果要求选择后端服务，选择不使用云服务。当前项目不需要云开发环境。
5. 点击导入后点击工具栏的“编译”，默认首页是 `pages/home/home`。
6. 在模拟器底部切换“首页 / 问答 / 我的”。办事指南已移入首页「办事指南 ›」和「我的 → 办事指南」。建议先使用标准手机尺寸或 iPhone 模拟器查看。

项目没有任何网络请求，**不需要关闭合法域名校验**。如果编译遇到 AppID 相关提示，先检查第 3 步，不要把它当成 HTTPS 配置问题。

游客或测试模式的权限取决于微信当前工具与账号设置；它们适合先在模拟器展示。需要手机真机预览、多人体验或上传时，再使用具备相应权限的 AppID。**有 AppID 和有 HTTPS 域名是两件事**：本项目即便使用真实 AppID，也不会因此需要自建域名。

## 推荐的 3 分钟展示顺序

| 时间 | 操作 | 说明要点 |
| --- | --- | --- |
| 0:00–0:30 | 从首页点击“校园卡丢了怎么办？” | 统一咨询入口，展示步骤与回答来源 |
| 0:30–1:00 | 点回答中的“查看当前指南”，再返回问答 | 展示来源、版本、适用范围；点一次“有帮助” |
| 1:00–1:30 | 输入“图书馆”，选择推荐问题，再输入“那周末呢？” | 演示澄清和简单上下文承接 |
| 1:30–2:00 | 输入“月球上可以种什么花？” | 未收录问题明确提示无法确认，不编造答案 |
| 2:00–2:30 | 输入“食堂遗失物品怎么找回？”；再到“我的”切换为审核员，进入工作台发布预置待审条目 | 发布前查不到；审核后知识生效 |
| 2:30–3:00 | 回到问答，再次输入同一个食堂问题 | 现在得到带来源的新答案，完成知识维护闭环 |

两分钟展示可直接使用预置待审知识。时间充足时再展示完整起草过程：

1. “我的”切换“知识维护人员” → “知识管理与审核”。
2. 点“新建演示知识”，填写标题、答案、咨询途径、来源、范围；分类与来源有默认值。
3. 保存后到“草稿 / 退回”，点击“提交审核”。待审条目不能直接改动。
4. 返回“我的”切换“知识审核员”，进入“待审核”，检查全文与来源后发布；也可填写退回原因。
5. 再切回学生，查找刚发布的知识。新增自定义问法可填写“同义问法”，标题本身也可以直接提问。

修订已有知识：维护人员在工作台“知识库”点击“创建修订草稿”，修改、保存、提交，再由审核员发布。审核前继续使用原版本，审核后版本号加一。历史对话保留当时答案和来源版本；点击来源查看的是当前指南。

## 缩减了哪些需求

| 原需求 | 演示版处理 |
| --- | --- |
| 统一身份认证、多级权限 | 用户端三种使用者身份（游客 / 学生 / 教师、行政人员）决定能访问哪些知识库；身份由客户端上报，不代表真实安全认证 |
| 知识维护与审核的角色 | 维护人员、审核员是管理端角色，**不在用户端小程序里**；能力由 `knowledge_base/scripts/kb_admin.py` 承接（起草 → 提交 → 驳回/发布 + 审计） |
| 多知识库资产 | 建了三个知识库的注册表与路由（公开指南 / 学生手册 / 教职工手册），但只有学生手册有真实语料，另两个是演示占位、内容待补 |
| 大模型生成、向量检索、置信度策略 | 本地同义问法和文本相似度匹配；只返回已发布答案原文，不显示伪造的准确率或置信度 |
| 多轮对话 | 支持紧接上一条命中知识的简单追问；无法可靠承接的问法会兜底 |
| 图片提问、流式输出 | 暂缓，先保持文字问答演示完整 |
| 服务端数据库、运营后台 | 用户端用本机缓存保存会话与反馈；知识资产与审核记录放在管理端 JSON + 命令行，不是 Web 后台 |
| 官方业务跳转 | 展示咨询途径；真实窗口、电话和链接待人工核实后补充 |
| 运营统计、日志 | 用户端只有本机消息数量与反馈数量；管理端有知识操作审计日志，非完整运营/审计系统 |
| 自动保留期限、备份、高并发 | 暂缓；用户端仅保留最近 120 条消息及对应反馈，支持手动复位 |

本地缓存不作为敏感信息存储。演示时使用公开样例问题，不要输入密码、证件号等个人信息。

## 项目结构

```text
campus-assistant/
  project.config.json       开发者工具导入配置
  miniprogram/
    app.js / app.json       应用启动、页面与底部导航
    app.wxss                公共样式
    data/libraries.js       知识库注册表（由 knowledge_base/scripts/export_libraries.py 生成，不要手改）
    data/knowledge.js       22 条已发布知识（按 kbId 归属知识库）；草稿不下发到用户端
    utils/qa.js             本地匹配、追问、澄清、范围外兜底、来源标注
    utils/store.js          本地缓存、身份、知识库过滤、会话、反馈、统计
    pages/home/             首页
    pages/chat/             问答页
    pages/services/         指南列表
    pages/detail/           指南详情
    pages/mine/             我的、身份切换与知识库清单
  scripts/check.js           零依赖逻辑与项目结构检查（含「用户端不得含管理端角色」的守卫）
```

替换本校资料时，从 `miniprogram/data/knowledge.js` 开始；**新增或调整知识库要改 `knowledge_base/data/libraries.json`
再重新生成 `data/libraries.js`**（步骤见 `knowledge_base/README.md`）。已经运行过的设备会优先读取缓存，
改完初始数据后到“我的”点击“恢复初始演示数据”，再重新查看。此操作会删除本机演示修改与对话，按钮有二次确认。

后续接真实问答时，可保留页面和返回字段，在服务层替换 `utils/qa.js` 的调用。模型密钥应保存在后端；届时再配置实际后端 HTTPS 服务与合法域名。

## 身份与知识库（v0.5）

用户端只有三种使用者身份，对应《校园智能客服与知识问答系统需求分析说明书》2.1 角色表里的
「游客」和「学生、教师/行政人员」两行，在「我的 → 切换 ⇄」里切换。
**每个身份有自己能访问的知识库**，这一点在「我的」页直接列出来（名称、版本、建设状态、文档数、本机条目数、能不能查）。

| 身份 | `identityType` | 可访问知识库 | 限制 |
| --- | --- | --- | --- |
| 游客 | `guest` | 校园公开办事指南 | 会话不写本机存储；查不到需登录身份的知识 |
| 学生 | `student` | 公开指南、学生手册 | 查不到教职工手册 |
| 教师/行政人员 | `teacher` | 公开指南、学生手册、教职工手册 | 只能问答与查看指南 |

2.1 角色表里的另外两行——**知识维护人员**与**知识审核员**——不在小程序里。它们是对系统负责、
不是使用系统的角色，放进用户端会带来两个实际问题：一是主线演示被管理功能冲淡，
二是「切换演示身份」看起来像真的能用客户端授予权限。它们的职责改由管理端工具承接：

```powershell
cd knowledge_base
python scripts\kb_admin.py selftest    # 字段校验、越权、自审阻断、版本递增、乐观锁、审计（纯内存，随时可跑）
python scripts\kb_admin.py draft --actor maintainer --kb public-guide --category 后勤 ^
    --title "食堂遗失物品怎么找回？" --answer "……" --source "课题演示资料 · 后勤办事指南" ^
    --channel "食堂服务台" --scope "演示校区 · 全体师生" --long-term
python scripts\kb_admin.py submit --actor maintainer --id draft-xxx
python scripts\kb_admin.py review --actor reviewer --id draft-xxx --approve
python scripts\kb_admin.py log
```

它把 2.3 节的审核流程和 FR-25/26/27/34 的规则都实现了：必填字段与时间区间校验、
已提交版本冻结、**禁止作者自审**、驳回必须填原因、修订版本递增、乐观锁防覆盖、审计只追加。
注册表里这两个身份仍保留（`app: false`），后端的 `staff` 身份范围也照旧，
所以「身份 → 知识库」这条路由的前后端映射没有断。

知识库注册表是**唯一数据源** `knowledge_base/data/libraries.json`，小程序端的 `data/libraries.js`
由 `knowledge_base/scripts/export_libraries.py` 生成，后端 `backend/app/libraries.py` 读同一份 JSON：

| 知识库 | 面向身份 | 本条演示库里的条目 | 建设状态 |
| --- | --- | --- | --- |
| 校园公开办事指南 `public-guide` | 游客及所有登录身份 | 20 | 内容已录，仅本机演示（未接入在线检索） |
| 学生手册 `student-handbook` | 学生、教师（管理端 staff 也可） | 1（另在线上有 586 块手册原文） | 已接入在线检索 |
| 教职工手册 `staff-handbook` | 教师、行政人员（管理端 staff 也可） | 1 | **内容待补** |

**知识条目靠 `kbId` 归属到知识库，身份可见性完全由知识库的 `audience` 决定**，条目自己不再声明身份范围。
过滤统一发生在 `store.getKnowledge()`，问答页、办事指南和详情页都从它取数据。
因此游客提问「教职工在职证明」拿到的是「知识库没有依据」，**不会透露受限条目是否存在**
（对应说明书「权限不满足时不透露受限条目是否存在」）。

这里有一处容易漏掉的细节：本地检索如果只过滤、不兜底，游客问「教职工在职证明怎么办理？」会命中
相似度 0.5 的公开条目「在读证明怎么办理？」并给出错误答案。所以 `qa.js` 会同时拿到
`store.getRestrictedKnowledge()`（当前身份看不到的条目），当范围外存在**达到阈值且比范围内更贴近**
的条目时直接走兜底话术，而不是拿一条不相关的公开条目硬答。

### 回答里的知识来源

每条回答的来源卡片固定给出四件事：

```text
知识来源
知识库：学生手册 · hb-2017-v1 · 已接入检索
文档：住宿管理规定
位置：第二十二条 · 第 174 页
条目 v1 · 更新 2017-09-01 · 适用范围：演示校区 · 在校学生事务
```

离线路径的这些字段由 `store.getKnowledge()` 的 `decorate()` 注入（知识库名/版本 + 文档 + 条号/页码），
在线路径由后端 `citations[].kb` 返回。两边字段同名，所以来源卡片只有一套模板。

### 还有三条按身份生效的规则

1. 游客会话只存在内存里（`store.js` 的 `guestSession`），不写入 `wx.Storage`；切换身份、点「新对话」或重启小程序后都取不回来。
2. 游客的「有帮助/待改进」只关联当前匿名会话，不写入本机长期反馈档案。
3. 用户端没有任何知识维护接口：`store` 不导出 `saveDraft / submitDraft / reviewDraft`，
   `app.json` 不再注册工作台页面，`check.js` 里有专门的守卫断言（`test_user_app_has_no_admin_roles` 在后端侧也守一遍）。

### 在线模式怎么配合

问答请求把身份作为 `scope.identity_type` 上报后端（`utils/api.js`），后端据此决定检索哪些知识库，并返回
`knowledge_bases`（本次检索了哪些库）、`kb_pending`（还能访问但没建索引的库）、`kb_gap`（一个能检索的都没有）。

- 游客在线提问：后端返回 `kb_gap: true`，问答页顶部出现蓝色提示条说明原因，并**自动改用本机已发布的公开知识**回答，来源卡片照样标注「校园公开办事指南」。
- 教师在线提问：检索学生手册，答案末尾会注明「教职工手册尚未接入检索，本次没有检索它」。
- 后端没启动：直接回退本机知识，和以前一样。

> **仍然没做**：`scope.identity_type` 由客户端上报，**客户端可以谎报身份**（游客改成 `teacher` 就能查教师库）。
> 真上线要按 FR-02 接统一身份认证，由服务端从凭据推导身份。详见 `backend/README.md` 的「还没做」。

## 在线检索模式（已接通）

问答页现在有两条路径：

```text
在线：utils/api.js → http://127.0.0.1:8000/v1/ask → 按身份选库 → bge 检索 + 重排 → 条文原文 + 出处 + 所属知识库
离线：utils/qa.js  → 本机 22 条演示知识（按身份过滤；后端未启动、请求失败或 kb_gap 时回退）
```

界面上会显示当前模式：顶栏「在线检索 · 学生手册 2017 版」或「本地演示」，输入框下方同步提示。

### 怎么看效果

1. 先启动后端（见 `../backend/README.md`）：
   ```powershell
   & "..\knowledge_base\.venv\Scripts\python.exe" ..\backend\run.py --port 8000
   ```
   看到「模型预热完成」约需 12 秒；预热期间 `/v1/health` 返回 `status=warming`。
2. 开发者工具里点「编译」。顶栏出现「在线检索」即接通。
3. 试这几句：
   - `宿舍几点熄灯` → 住宿规定第二十二条，带页码
   - `挂科了还能补考吗` → 学籍规定第二十二条（同义改写也能命中）
   - `图书馆几点开门` → 明确说查不到，不编造
   - `帮我报修宿舍漏水` → 说明不代办，给官方渠道
4. 关掉后端再问一句，会自动退回「本地演示」，页面不白屏——这是刻意的降级设计。
5. 到「我的」切换身份再看一遍问答与指南：游客只有 20 条公开知识、且不留本机历史；切到教师、行政人员能看到 22 条。这个范围差异由本地演示数据决定，理由见上文「身份与适用范围」。

### 换服务器地址

只改 `miniprogram/utils/api.js` 第 8 行：

```js
const BASE_URL = 'http://127.0.0.1:8000';   // 换服务器/域名只改这一行
```

注意：**模拟器可以用 http，真机必须 HTTPS**（微信只对模拟器放开「不校验合法域名」）。

### 字段映射

后端返回 `behavior` 五档，页面只认三种展示形态，映射写在 `api.js` 的 `KIND` 里：

| 后端 behavior | 页面展示 |
| --- | --- |
| answer / answer_with_caveat | 知识库答复 + 来源卡片 |
| clarify | 请补充信息 + 推荐问法 |
| refuse_noanswer / refuse_boundary | 暂无法确认 + 建议途径 |

后端知识块（`hb-xxx`）不在小程序本地知识库里，所以来源卡片显示「不可跳转」；本地演示的条目仍可点进详情页。

## 界面结构（v0.5）

> 首页那段描述是早期版本留下的，和当前代码不完全一致（入口卡文字与数量以 `pages/home/` 为准）；其余部分已对齐到当前代码。主色是绿色 `#176b5b`，定义在 `app.wxss` 的 `page` 自定义属性里。

底部入口：**首页 / 问一问 / 办事指南 / 我的**。设计基调是白底、单一主色、大留白、圆角卡片、无重阴影；颜色全部集中在 `app.wxss` 的 `page` 自定义属性里，换主题只改那一段。

# 校园知答：微信小程序演示框架

这是依据《校园智能客服与知识问答系统需求分析说明书》搭建的原生微信小程序。直接在微信开发者工具中导入即可开始本地演示，不需要 npm 安装、后端、云开发环境或 HTTPS 域名。

## 现在可以演示什么

- 首页：常用服务、常见问题、已发布知识数量。
- 问一问：已发布知识的关键词与相似问法检索、简单追问、分类澄清、无答案提示、来源和版本、有帮助/待改进反馈。
- 办事指南：按分类与关键词查找，查看办理步骤、咨询窗口和资料来源。
- 我的：切换学生/知识维护人员/知识审核员，查看本机统计和最近操作。
- 知识工作台：新建或修订草稿 → 提交审核 → 退回或发布。发布后本机问答和指南立即更新。
- 演示复位：恢复 20 条初始知识及 1 条待审核知识，方便下一轮展示。

**当前是本地检索原型，没有接入大模型、RAG、OCR、真实学校登录、真实个人业务查询或报修工单。** 所有样例制度、窗口和时间都明确标注为演示资料。没有配置未经核实的学校电话和外部链接。

## 导入微信开发者工具

1. 打开微信开发者工具，选择“小程序”，然后“导入项目”。
2. 项目目录选本 README 所在的 **campus-assistant 文件夹**，不要选它里面的 miniprogram 文件夹。
3. 项目名可填写“校园知答”。配置里的 `touristappid` 用于游客本地调试。如果工具提示需要 AppID，按界面提供的“测试号”或“不使用 AppID / 游客模式”创建；已有小程序 AppID 也可以使用。
4. 如果要求选择后端服务，选择不使用云服务。当前项目不需要云开发环境。
5. 点击导入后点击工具栏的“编译”，默认首页是 `pages/home/home`。
6. 在模拟器底部切换“首页 / 问一问 / 办事指南 / 我的”。建议先使用标准手机尺寸或 iPhone 模拟器查看。

项目没有任何网络请求，**不需要关闭合法域名校验**。如果编译遇到 AppID 相关提示，先检查第 3 步，不要把它当成 HTTPS 配置问题。

游客或测试模式的权限取决于微信当前工具与账号设置；它们适合先在模拟器展示。需要手机真机预览、多人体验或上传时，再使用具备相应权限的 AppID。**有 AppID 和有 HTTPS 域名是两件事**：本项目即便使用真实 AppID，也不会因此需要自建域名。

## 推荐的 3 分钟展示顺序

| 时间 | 操作 | 说明要点 |
| --- | --- | --- |
| 0:00–0:30 | 从首页点击“校园卡丢了怎么办？” | 统一咨询入口，展示步骤与回答来源 |
| 0:30–1:00 | 点回答中的“查看当前指南”，再返回问答 | 展示来源、版本、适用范围；点一次“有帮助” |
| 1:00–1:30 | 输入“图书馆”，选择推荐问题，再输入“那周末呢？” | 演示澄清和简单上下文承接 |
| 1:30–2:00 | 输入“月球上可以种什么花？” | 未收录问题明确提示无法确认，不编造答案 |
| 2:00–2:30 | 输入“食堂遗失物品怎么找回？”；再到“我的”切换为审核员，进入工作台发布预置待审条目 | 发布前查不到；审核后知识生效 |
| 2:30–3:00 | 回到问答，再次输入同一个食堂问题 | 现在得到带来源的新答案，完成知识维护闭环 |

两分钟展示可直接使用预置待审知识。时间充足时再展示完整起草过程：

1. “我的”切换“知识维护人员” → “知识管理与审核”。
2. 点“新建演示知识”，填写标题、答案、咨询途径、来源、范围；分类与来源有默认值。
3. 保存后到“草稿 / 退回”，点击“提交审核”。待审条目不能直接改动。
4. 返回“我的”切换“知识审核员”，进入“待审核”，检查全文与来源后发布；也可填写退回原因。
5. 再切回学生，查找刚发布的知识。新增自定义问法可填写“同义问法”，标题本身也可以直接提问。

修订已有知识：维护人员在工作台“知识库”点击“创建修订草稿”，修改、保存、提交，再由审核员发布。审核前继续使用原版本，审核后版本号加一。历史对话保留当时答案和来源版本；点击来源查看的是当前指南。

## 缩减了哪些需求

| 原需求 | 演示版处理 |
| --- | --- |
| 统一身份认证、多级权限 | 三种演示角色切换，流程中检查当前角色；不代表真实安全认证 |
| 大模型生成、向量检索、置信度策略 | 本地同义问法和文本相似度匹配；只返回已发布答案原文，不显示伪造的准确率或置信度 |
| 多轮对话 | 支持紧接上一条命中知识的简单追问；无法可靠承接的问法会兜底 |
| 图片提问、流式输出 | 暂缓，先保持文字问答演示完整 |
| 服务端数据库、运营后台 | 本机缓存和小程序内管理页；不同设备不共享数据 |
| 官方业务跳转 | 展示咨询途径；真实窗口、电话和链接待人工核实后补充 |
| 运营统计、日志 | 本机消息数量、反馈数量、待审数量、最近操作；非完整运营/审计系统 |
| 自动保留期限、备份、高并发 | 暂缓；仅保留最近 120 条消息、对应反馈及最近 100 条操作，支持手动复位 |

本地缓存不作为敏感信息存储。演示时使用公开样例问题，不要输入密码、证件号等个人信息。

## 项目结构

```text
campus-assistant/
  project.config.json       开发者工具导入配置
  miniprogram/
    app.js / app.json       应用启动、页面与底部导航
    app.wxss                公共样式
    data/knowledge.js       20 条初始知识、分类和 1 条待审核知识
    utils/qa.js             本地匹配、追问、澄清与兜底
    utils/store.js          本地缓存、角色、知识审核、反馈、统计
    pages/home/             首页
    pages/chat/             问答页
    pages/services/         指南列表
    pages/detail/           指南详情
    pages/mine/             我的与角色切换
    pages/manage/           知识维护和审核
  scripts/check.js           零依赖逻辑与项目结构检查
```

替换本校资料时，从 `miniprogram/data/knowledge.js` 开始。已经运行过的设备会优先读取缓存，改完初始数据后到“我的”点击“恢复初始演示数据”，再重新查看。此操作会删除本机演示修改与对话，按钮有二次确认。

后续接真实问答时，可保留页面和返回字段，在服务层替换 `utils/qa.js` 的调用。模型密钥应保存在后端；届时再配置实际后端 HTTPS 服务与合法域名。

## 本地检查

在项目目录运行 `node scripts/check.js`。检查使用内存模拟微信缓存，不会改变开发者工具中的演示数据。真实布局和交互还需在开发者工具模拟器中预演。

# 演示脚本（模拟器，约 6 分钟）

## 0. 启动后端

```powershell
cd backend
python run.py --port 8000
```

看启动日志里的三行状态，演示前先确认是你想要的配置：

| 日志 | 含义 |
| --- | --- |
| `生成模型  deepseek / deepseek-chat` | 回答由大模型依据条文整理。显示「未配置密钥」则回答是条文原文 |
| `登录方式  微信登录` | 显示「开发模式」则是按设备发的本地账号 |
| `检索器就绪（vector）` | 显示 `lexical` 则是关键词保底检索，口语问法容易查不到 |

配置方法见 `../backend/README.md`。**下面的脚本按「已配置生成模型」来写**；没配时回答是手册原文，
第 2 节的第 2、3 步表现不同，已在表里注明。

## 1. 打开小程序

微信开发者工具 → 导入项目 → 目录选 **`campus-assistant`**（不是里面的 `miniprogram`）→ 编译。

第一眼确认：

1. 首页绿色区域顶上写着「游客，可查国家教育法规」。
2. 底部四个入口：首页 / 问答 / 手册 / 我的，图标正常显示。
3. 首页有一条黄色提示：绑定在校身份后可查 25 份校内规章。

如果首页显示「连不上问答服务」，是后端没启动或地址不对（`miniprogram/utils/api.js` 的 `BASE_URL`）。

## 2. 主线：问一个问题，核对出处（约 2 分钟）

先到「我的」→「我是学生」→ 绑定。回到首页，顶上变成「学生，可查国家教育法规、学生手册」。

| # | 操作 | 期望看到 | 讲解要点 |
| --- | --- | --- | --- |
| 1 | 首页输入框里输入「宿舍几点熄灯」，点「提问」 | 跳到问答页，显示「正在查手册…」，随后出回答 | 首页就是提问入口；下面「同学们常问」的问题来自手册的常见问法，保证答得出来 |
| 2 | 看回答 | 几句直接回答问题的话，下面是「依据以下条文整理」和一条红色竖线的出处：第二十二条 · 《…学生住宿管理规定》· 第 174 页 | 回答是整理过的，但每句都有出处。**没配模型时**：这里是宋体的条文原文，出处标题是「手册原文出自」 |
| 3 | 点那条出处 | 进入条文原文页：朱红的「第二十二条」、宋体全文、页码 | 任何回答都能一步核对到原文，这是和普通聊天机器人最大的区别 |
| 4 | 点「下一条」 | 翻到第二十三条 | 可以顺着读上下文 |
| 5 | 返回问答，点回答下面的追问建议 | 新一轮问答 | 追问建议是模型根据条文给的，保证能答。**没配模型时**是相近的常见问法 |
| 6 | 问「挂科了还能补考吗」 | 命中学籍管理规定的补考条款 | 口语问法也能查到。**关键词检索且没配模型时**这句会被拒答，换成「课程不及格怎么补考」 |

## 3. 不该答的不答（约 1 分半）

| # | 操作 | 期望看到 | 讲解要点 |
| --- | --- | --- | --- |
| 1 | 问「图书馆几点开门」 | 「手册里没有找到依据」，没有出处 | 手册里没有图书馆的文件。查不到就说查不到，不编 |
| 2 | 问「帮我报修一下宿舍漏水」 | 「这件事我办不了」，说明不代办，给出该去哪里 | 立刻返回，不进检索 |
| 3 | 问「查一下我的期末成绩」 | 同上：不查个人数据 | |
| 4 | 问「奖学金」 | 「需要再具体一点」+ 几个可选的问题 | 话题太泛先澄清，不猜 |
| 5 | 问「手册写勤工助学 15 元一小时，现在还是吗」 | 回答末尾多一段：这是 2017 年版的表述，以现行文件为准 | 手册可能过期，如实提示 |

## 4. 翻手册（约 1 分钟）

| # | 操作 | 期望看到 |
| --- | --- | --- |
| 1 | 点底部「手册」 | 28 份文件分 7 类：国家法规、学籍与成绩、毕业与学位、纪律与申诉、课外与学分、奖励与资助、校园生活 |
| 2 | 搜「熄灯」 | 第一条就是住宿规定第二十二条，带命中片段 |
| 3 | 搜一个手册里没有的词 | 提示条文里没有这个词，可以「去问答页问这句」 |
| 4 | 点任意一份文件 | 按章分组的条文列表，每条带预览和页码 |

## 5. 身份决定能查什么（约 1 分半）

| # | 操作 | 期望看到 | 讲解要点 |
| --- | --- | --- | --- |
| 1 | 「我的」→「解除身份，回到游客」 | 「我能查什么」里学生手册变成「需相应身份」 | |
| 2 | 回问答页 | 之前的对话已清空，顶栏写「对话不保存」 | 身份变了，旧对话里可能有无权看的内容 |
| 3 | 游客身份问「宿舍几点熄灯」 | 「手册里没有找到依据」，**回答里不提学生手册** | 不透露受限内容是否存在 |
| 4 | 游客身份问「对学校的处分不服可以申诉吗？」 | 正常回答，出处是《普通高等学校学生管理规定》 | 国家法规是公开的，游客能查 |
| 5 | 「手册」页 | 只有 3 份文件，底部提示还有 25 份需要绑定身份 | 浏览和问答用同一套规则 |
| 6 | 「我的」→「我是教师/行政人员」 | 弹出口令输入框（后端配了 `teacher_code` 时） | 教师身份不是谁都能点 |
| 7 | 绑定学生后看「提问记录」 | 之前以学生身份问过的问题都在 | 记录存在服务端，换手机也能看 |

被问到「身份是不是随便选的」时如实回答：**目前是自行声明**，页面上也标着「尚未经学校统一身份认证核验」。
已经做到的是：身份由服务端按登录令牌认定，客户端改请求参数冒充不了；真正的核验要接学校的统一身份认证。

## 6. 后端出问题时（约半分钟）

关掉后端（Ctrl+C），在问答页再问一句：气泡里显示「这次没有问成功」和「重新提问」按钮，问题没有丢。
重新启动后端，点「重新提问」，得到回答。

小程序本身不带知识，所以后端不可用时不会给出任何回答——这是有意的：不用过期或不完整的本地内容顶替。

## 7. 已知不足（主动说明）

| 现象 | 原因 |
| --- | --- |
| 身份可以自行声明 | 没有接学校统一身份认证 |
| 只能在模拟器里跑 | 用的是游客 AppID 和本机 http 地址；真机需要正式 AppID、公网服务器和备案的 HTTPS 域名 |
| 回答偶尔引用了不太贴切的条文 | 检索前几名里混入了相近的条文。出处可点开核对 |
| 模型可能误解条文 | 后端校验了引用和数字，但拦不住「数字没错、意思理解错」的情况 |
| 没配模型时口语问法容易查不到 | 关键词检索的局限，见 `../backend/README.md` |
| 回答要等几秒，不是逐字出现 | 没有做流式输出 |
| 教职工手册是空的 | 没有语料 |
| 手册是 2017 年版 | 只有这一版 PDF |

# 模拟器演示脚本（约 6 分钟）

## 0. 启动后端

```powershell
cd "D:\校园智能问答系统\AI_chat\backend"
& "..\knowledge_base\.venv\Scripts\python.exe" run.py --port 8000
```

看到「模型预热完成」约需 25–30 秒。预热期间 `/v1/health` 返回 `status=warming`，小程序会先显示「本地」，预热完刷新一次即可变「在线」。

验证后端活着：

```powershell
curl.exe -s http://127.0.0.1:8000/v1/health
```

## 1. 打开小程序

微信开发者工具 → 导入项目 → 目录选 **`campus-assistant`**（不是里面的 `miniprogram`）→ 编译。

**第一眼要确认四件事**：

1. 首页右上角状态胶囊是「**● 在线**」（灰色「本地」说明连不上后端）
2. 底部四个 tab：**首页 / 问一问 / 办事指南 / 我的**
3. 「我的」顶部身份卡显示当前身份（默认**学生**），点「切换 ⇄」只有**三种使用者身份**：游客、学生、教师/行政人员
4. 「我的」里的**知识库清单**：校园公开办事指南（本机演示）、学生手册（已接入检索）、教职工手册（**内容待补**）——每个身份能查哪几个看「可查/不可查」标签

> 知识维护人员与知识审核员**不在小程序里**。它们是对系统负责而不是使用系统的角色，
> 答辩时如果被问到，回答：用户端只放使用者身份，维护/审核由管理端工具
> `knowledge_base/scripts/kb_admin.py` 承担，职责分离和审计都在那边。

## 2. 演示顺序

| # | 操作 | 期望看到 | 讲解要点 |
| --- | --- | --- | --- |
| 1 | 首页点「宿舍几点熄灯？」 | 跳到问答页，先出现三点跳动「正在检索学生手册…」，约 1 秒后出答案 | 有加载反馈，不是干等 |
| 2 | 看答案卡片 | 正文约 6 行后折叠，点「展开全文」看全；下方「知识来源」标出 **知识库：学生手册 · hb-2017-v1** → 文档 → 第二十二条 · 第174页 | 每条回答都能说清出自哪个库、哪条、哪页 |
| 3 | 点「宿舍里哪些电器不能用？」 | 新的问答，命中住宿规定第四十一条 | 推荐追问来自题库，不是随机 |
| 4 | 问「图书馆几点开门？」 | 灰色标签「暂无法确认」，回答明确说检索的知识库里没有、不做推测 | **这是核心卖点**：不知道就说不知道 |
| 5 | 问「帮我报修宿舍漏水」 | 立刻返回（约 0 毫秒），橙色边界提示：不代为受理、不派发工单 | 需求文档 FR-20 的答复边界 |
| 6 | 问「奖学金」 | 橙色「需要补充信息」+ 3 条推荐问法 | 缺槽位时先澄清，不瞎猜 |
| 7 | 问「手册写勤工助学 15 元一小时，现在还是吗？」 | 答案末尾多一段「以现行文件为准」 | 时效提示（2017 版手册 vs 现行文件） |
| 8 | 点「有帮助」 | Toast「谢谢你的反馈」，按钮高亮 | 反馈同时上报后端 |

## 3. 展示身份与知识库（约 1 分半）

需求文档 2.1 里的三种**使用者**身份在这里演示，在「我的 → 切换 ⇄」里切；每个身份对应自己的知识库。

| # | 操作 | 期望看到 | 讲解要点 |
| --- | --- | --- | --- |
| 1 | 打开「我的」看知识库清单 | 三个库各带状态标签：公开指南＝本机演示、学生手册＝已接入检索、教职工手册＝**内容待补** | 「每个身份有自己的知识库」是这一版的重点 |
| 2 | 切到**游客** | 问答页顶栏下细条写「可查知识库：校园公开办事指南」；在线问一句会出现蓝色提示条，说明该库未接入检索、已改用本机知识 | 身份先决定能查哪些库，游客的库还没接索引 |
| 3 | 游客身份问「教职工在职证明怎么办理？」 | 兜底「知识库没有依据」 | 不透露受限条目是否存在（说明书明文要求） |
| 4 | 切到**教师/行政人员**再问同一句 | 给出答案，来源卡片标 **知识库：教职工手册 · 待补** → 文档 → 条目版本 | 同一条知识按所属知识库的身份范围开放 |
| 5 | 教师身份问一个手册里的问题（如「宿舍几点熄灯」） | 正常作答，来源卡片标 **知识库：学生手册 · hb-2017-v1 · 已接入检索**；答案末尾注明「教职工手册尚未接入检索，本次没有检索它」 | 不拿别的库冒充全部知识 |
| 6 | 切到**学生**问「教职工在职证明怎么办理？」 | 又变回兜底 | 教师库对学生同样不可见 |
| 7 | 游客身份问一句并点「有帮助」，再切到学生 | 刚才的问答和评价都不见了 | 匿名会话只在内存，切换身份即失效 |

本机离线检索的可见条数：游客 20 条、学生 21 条、教师 22 条。

## 4. 展示知识维护与审核（管理端，约 1 分钟）

这一步**不在小程序里**，用命令行演示同一套规则（需求文档 2.3 节 + FR-25/26/27/34）：

```powershell
cd <项目根目录>\knowledge_base
python scripts\kb_admin.py selftest        # 一次跑完全部规则，纯内存，不会改 data/
```

要现场走一遍流程就按这四步（数据落在 `data/kb_drafts.json` 等文件，已被 .gitignore 忽略）：

```powershell
$py = "<项目根目录>\knowledge_base\.venv\Scripts\python.exe"   # 或你自己的 Python
& $py scripts\kb_admin.py draft --actor maintainer --kb public-guide --category 后勤 `
    --title "食堂遗失物品怎么找回？" --answer "可先向食堂服务台询问。" `
    --source "课题演示资料 · 后勤办事指南" --channel "食堂服务台" --scope "演示校区 · 全体师生" --long-term
& $py scripts\kb_admin.py submit --actor maintainer --id <上一步输出的草稿 ID>
& $py scripts\kb_admin.py review --actor maintainer --id <草稿 ID> --approve   # 会被拒：职责分离
& $py scripts\kb_admin.py review --actor reviewer   --id <草稿 ID> --approve   # 通过，发布 v1
& $py scripts\kb_admin.py log
```

讲解要点：**维护人员审核自己的稿子会被直接拒掉**（作者不能审核本人版本）；驳回必须填原因；
修订后版本号递增而不是覆盖；每一步都进了审计日志（操作主体 / 动作 / 对象 / 时间 / 结果）。

## 5. 展示"离线降级"

关掉后端（Ctrl+C），在问答页再问一句：顶栏变成「本地演示」，仍能回答（用本机 22 条示例知识，按身份过滤）。再启动后端，刷新页面变回「在线」。

这一条对应需求文档 NFR-02 的降级要求。

## 6. 已知不足（主动说明，别等被问）

| 现象 | 原因 | 如实解释 |
| --- | --- | --- |
| 回答是条文原文，不是自然语言 | 未接生成模型 | 先保证每句有依据；接 7B 后语言会通顺，但模板路径要保留做降级 |
| 问「学分没修满能拿毕业证吗」答成了第五十五条（转学转专业毕业） | 否定式问法的高置信错配 | 阈值拦不住这类，需要生成层复核；评测集里同类问法（ev-057）是过的 |
| 同义问法准确率 71% | 召回不足 | 已定位，下一步加 FAQ 索引或第二路嵌入 |
| 来源卡片不能点进详情 | 后端知识块不在小程序本地库里 | 演示版保留本地详情页，接后端时应该做"条文详情"页 |
| 知识维护不在小程序里 | 维护/审核是对系统负责的内部角色，放进用户端会让「切换演示身份」看起来像真能用客户端授予权限 | 用户端只放使用者身份是刻意的；维护与审核由 `knowledge_base/scripts/kb_admin.py` 承担，规则和审计齐全，但还没做 Web 管理界面 |
| 管理端发布还没自动同步到小程序 | `kb_admin.py` 的发布结果落在 `data/kb_published.json`，没有导出成 `miniprogram/data/knowledge.js` | 目前小程序里的 22 条是随包发布的已发布集合；下一步加一个导出步骤就能闭环 |
| 教职工手册是空的 | 真实语料还没找来 | 注册表、路由、来源标注都已就绪，按 `knowledge_base/README.md` 的五步把语料放进 `data/staff_chunks.jsonl` 并建索引即可 |
| 身份可以被客户端谎报 | `scope.identity_type` 由小程序上报，服务端直接采信（游客改成 teacher 就能查教师库） | 说明书 FR-02 要求统一身份认证；演示环境用模拟身份，上线要由服务端从凭据推导身份 |
| 只能模拟器 | 游客 AppID + 本地 http | 真机需要 AppID + 备案 HTTPS 域名 |

# 后端 API（可用）

基于《杭州电子科技大学学生手册》的问答服务。检索层复用 `knowledge_base/kb/`，后端只做
「策略判断 + 契约包装 + 会话/反馈」。

## 启动

```powershell
$py = "D:\校园智能问答系统\AI_chat\knowledge_base\.venv\Scripts\python.exe"
cd "D:\校园智能问答系统\AI_chat\backend"
& $py run.py --port 8000
```

首次启动会加载 bge + 重排模型（约 12 秒，占显存 3.5 GB）；之后每个请求约 0.5–1 秒。

- 接口说明：<http://127.0.0.1:8000/docs>
- 健康检查：<http://127.0.0.1:8000/v1/health>
- 冒烟测试：`& $py tests\smoke_api.py`（服务需先启动）

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/v1/health` | 状态、模型、索引指纹、语料版本 |
| POST | `/v1/ask` | 问答，返回行为、答案、引用、置信度、推荐问法 |
| POST | `/v1/feedback` | 反馈，追加写入 `data/feedback.jsonl` |
| GET | `/docs` | 接口说明页 |

```powershell
curl.exe -s -X POST http://127.0.0.1:8000/v1/ask -H "Content-Type: application/json" -d "{\"question\":\"宿舍几点熄灯\"}"
```

## 实测行为（六类各一例）

| 输入 | behavior | 置信度 | 耗时 | 引用 |
| --- | --- | --- | --- | --- |
| 宿舍几点熄灯 | answer | 0.90 | 1058 ms | 3 条（hb-510 住宿规定第二十二条） |
| 挂科了还能补考吗 | answer | 0.74 | 809 ms | 3 条（hb-142 第二十二条） |
| 图书馆几点开门？ | refuse_noanswer | 0.08 | 852 ms | 0（手册无图书馆文件） |
| 帮我报修一下宿舍漏水 | refuse_boundary | 0.00 | 2 ms | 0（不代办，越界规则直接拦） |
| 查一下我的期末成绩 | refuse_boundary | 0.00 | 17 ms | 0（不查个人数据） |
| 奖学金 | clarify | 0.30 | 16 ms | 0 + 3 条推荐问法 |

参数校验也验过：空问题返回 `400 EMPTY_QUESTION`，未知路径返回 `404 NOT_FOUND`。

## 策略层怎么判断

`app/answer.py`，顺序是**先拦越界、再澄清、最后才检索**：

```text
① 越界规则（正则）  → refuse_boundary，不检索
② 只有话题词        → clarify + 推荐问法
③ 检索（hybrid+rerank）
④ 置信度 < 0.42     → refuse_noanswer
⑤ 置信度 < 0.55 或前两名差 < 0.02 → clarify
⑥ 其余              → answer（条文原文 + 出处）
```

阈值在 `backend/config.json` 的 `answer_policy` 里，可调不用改代码。

两条刻意的设计：

- **越界不检索**。用户说「帮我报修」时，检索出住宿规定没有意义，反而容易被误读成「已受理」。
- **拒答不给假电话**。手册里没有窗口和电话，`boundary.channel` 就留空并注明「以官网公布为准」。宁可少给，不能编。

## 为什么是标准库而不是 FastAPI

这台机器上 `pip install fastapi` 会卡死（沙箱内 pip 反复空转，试了四次，每次十分钟无输出）。
标准库 `ThreadingHTTPServer` 零依赖、启动快，接口契约与 `app/schemas.py` 完全一致。
要换成 FastAPI 时只需把 `server.py` 的三个 handler 映射成路由函数，`answer.py` 不用动。

## 目录

```text
backend/
  run.py                启动入口
  config.json           后端阈值（answer_policy / session）
  app/
    __init__.py         导入 config，把 knowledge_base 加进 sys.path
    schemas.py          请求/响应字段定义（pydantic）
    config.py           合并知识库配置与后端阈值
    deps.py             检索器单例（懒加载，避免每请求重建模型）
    session.py          会话（内存，轮数上限 + 空闲过期）
    answer.py           策略层：越界/澄清/拒答/作答 + 模板回答
    server.py           HTTP 路由
  tests/smoke_api.py    六类行为冒烟
  tests/eval_policy.py  用 150 条评测集给策略层打分
  tests/smoke_miniprogram.js  小程序字段映射的契约测试（Node 模拟 wx.request）
```

## 策略层评测结果（150 条）

```powershell
& $py tests\eval_policy.py
& $py ..\knowledge_base\scripts\score_eval.py --predictions ..\knowledge_base\data\predictions_policy.json
```

| 指标 | 结果 | 目标 | 判定 |
| --- | --- | --- | --- |
| 无答案正确拒答率 | **100.0%**（20/20） | ≥ 95% | 达标 |
| 澄清题正确率 | **100.0%**（12/12） | ≥ 90% | 达标 |
| 边界合规率 | **100.0%**（8/8） | 无承诺性表述 | 达标 |
| 时效提示（answer_with_caveat） | **100.0%**（3/3） | — | 达标 |
| 纯检索 Top-3 命中率 | 89.1%（98/110） | ≥ 90% | 差 1 条 |
| 检索类端到端通过率 | 81.8%（90/110） | ≥ 90% | 未达标 |

分题型：标准问 42/45（93.3%）、同义问法 30/42（71.4%）、多轮追问 15/20（75%）。

### 阈值是量出来的，不是拍的

第一次跑用的是经验值（拒答 0.42 / 澄清 0.55），结果 45 道标准问里 19 道被误判成「澄清」。把置信度分布打出来后原因很清楚：

| 分组 | 最低 | P50 | 最高 |
| --- | --- | --- | --- |
| 检索命中的题 | **0.445** | 0.990 | 1.000 |
| 无答案题 | 0.000 | 0.026 | **0.259** |

两者之间是干净的分界（0.259 < 0.445），所以取 **0.35 作拒答线、0.40 作澄清带上限**：92 道命中全部保留，20 道无答案全部拒掉。经验值 0.55 之所以错，是因为 rerank logit 经 sigmoid 后分布两极化，中间地带几乎没有样本。

**另外停用了「前两名太接近就澄清」这条规则**（`clarify_gap: 0`）。原因是 sigmoid 在 0.9 以上饱和，两条候选项都是 0.99 时差值恒在 0.001 级，会把高置信度的正确回答误判成歧义——实测「学分没修满能拿毕业证吗」置信度 0.95 却被要求澄清。歧义改由「只给话题词」规则承担（12/12 命中）。

### 一个还没解决的错例

「学分没修满能拿毕业证吗？」会被高置信度（0.95）匹配到第五十五条（转学、转专业学生的毕业），而正确答案应是第五十七条（结业）。原因是该条含「修满要求的各类课程学分，达到毕业要求」，与问题字面高度重合，但语义相反（问的是没修满）。

这类**否定式/反义问法的高置信错配**，阈值和规则都拦不住，只能靠生成层复核或更强重排。评测集里对应的是 ev-057（「学分差一点能先拿结业证吗」），它命中正常——说明单题通过不代表同类问法都稳。

### 仍然没到 90% 的原因

不是策略层不会判断，而是**同义改写的检索还不够准**：13 道同义失败里 6 道是置信度掉到 0.35 以下被拒答、2 道落进澄清带、5 道检索没进前 3。标准问里 3 道是「前 3 命中但 top1 是另一条」，答案引用了相近但不是最优的条文。

换句话说：**策略层的四类行为已经全部达标，拖后腿的是召回**。下一步该动的是检索（加 bge-m3 第二路、把 30 条问答条目的问法做成 FAQ 索引），而不是继续调阈值。

## 还没做

- **生成层**：现在是「条文原文 + 出处」模板回答，能过「有出处、不编造」，但语言生硬。接 7B 后仍需保留本路径做降级。
- **多轮槽位补全**：现在只把上一轮问题拼进检索查询，校区/身份/学期这些槽位还没做抽取。
- **鉴权**：无。演示用；上线前要接统一身份认证（FR-02）。
- **限流与并发**：`ThreadingHTTPServer` 无连接数限制，GPU 单卡吞吐约 1.6 QPS，并发上来会排队。
